## NTU Water Risk Map — campus reporting and weather-aware routing

Revision: [`87cce94ba07d3977733b61992ee9c44905348cb1`](https://github.com/CdyTim630/ntu_water_map/tree/87cce94ba07d3977733b61992ee9c44905348cb1). Declared demo: [ntuwatermap.vercel.app](https://ntuwatermap.vercel.app/).

- **Verified implementation:** Next.js 14.2.35, React 18, TypeScript, React Leaflet, Recharts and optional Supabase. The [routing module](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/src/lib/denseGraph.ts) loads an OSM-derived GeoJSON graph, snaps endpoints, uses a binary-heap Dijkstra search, rejects bike-ineligible edges and weights distance by rain exposure, low-lying segments and nearby active reports. The [route API](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/src/app/api/route/route.ts) returns both weather-aware and shortest-route alternatives with comparison data. Reporting, drinking-water-station views and dashboard pages also exist.
- **Personal role:** The [report allocation table](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/report/report.tex#L151-L165) explicitly assigns 陳鼎元 **project integration and route-planning algorithms** in a six-person Introduction to Water Resources course team. All 27 reachable commits record CdyTim as author, but that does not supersede the report's division of frontend, API, data and hydrology work among teammates.
- **What to surface:** The path from public campus/geographic data and live-or-fallback weather to an explainable route comparison. A [server-side Gemini route](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/src/app/api/dashboard/ai-insights/route.ts) rewrites locally calculated management insights and falls back to local rules. Describe that as optional assisted summarization, not a trained flood-prediction model. Existing `report/screens/` images are candidate real project screenshots; check visible demo data before reuse.
- **Publication limits:** [Data access defaults to in-memory mock storage](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/src/lib/supabase.ts). [Dashboard regression](https://github.com/CdyTim630/ntu_water_map/blob/87cce94ba07d3977733b61992ee9c44905348cb1/src/app/api/stats/route.ts#L137-L174) uses fixed demo rainfall and a demo floor for report counts; its fit is not real-world predictive evidence. The current route-cost implementation differs from the older README formula, so prefer source over its performance claims. The checked-in Supabase schema denies anonymous update/delete while the admin helper still uses an anonymous client; the confirmation helper does not call the provided atomic RPC. Do not call persistence/admin integration production-ready or publish accuracy, risk-reduction or adoption numbers.

## Convenience-store Meal Optimizer — constrained recommendation coursework

Revision: [`828f7b41212cbcf1248ba003a39dd4bddefc2e3a`](https://github.com/CdyTim630/ntu114-2-or-final/tree/828f7b41212cbcf1248ba003a39dd4bddefc2e3a). No live demo declared.

- **Verified implementation:** Python, Gurobi, pandas/NumPy, Matplotlib and Flask. [MILP code](https://github.com/CdyTim630/ntu114-2-or-final/blob/828f7b41212cbcf1248ba003a39dd4bddefc2e3a/src/model_milp.py) models individual products and promotions, budget/calorie/count constraints, nutrition slack penalties, a sodium ceiling, meal structure and item/category recency. [GRASP/local search](https://github.com/CdyTim630/ntu114-2-or-final/blob/828f7b41212cbcf1248ba003a39dd4bddefc2e3a/src/heuristic_proposed.py) uses randomized candidate construction, local add/drop/swap moves and restarts. [Flask recommendation flow](https://github.com/CdyTim630/ntu114-2-or-final/blob/828f7b41212cbcf1248ba003a39dd4bddefc2e3a/webapp/app.py) maps a form to meal constraints, invokes a solver and maintains recent choices in a session.
- **Personal role:** The [README](https://github.com/CdyTim630/ntu114-2-or-final/blob/828f7b41212cbcf1248ba003a39dd4bddefc2e3a/README.md) names a four-person course team including 陳鼎元. CdyTim's [initial commit](https://github.com/CdyTim630/ntu114-2-or-final/commit/4cc2186d194a1b88a4efb2872741b696738a322d) publishes the original solver, heuristic, scrapers, web app and report artifacts; CdyTim also merges the later recommender branch. Subsequent changes are attributed to `goodmorning1226` and `ivyivych`. This supports initial code delivery and team participation, not sole design of every algorithm or report.
- **What to surface:** Translating an optimization model into a usable recommendation flow; exact-vs-heuristic comparison; price/nutrition ingestion; explicit hard constraints and soft tradeoffs. Published CSVs include 54 real-world and 90 random-instance solver rows, representing repeated solver comparisons rather than 144 independent scenarios. Use the checked-in form/result screenshots if their team context is acceptable.
- **Publication limits:** Reported feasibility and optimality-gap numbers were not reproduced and should not become headline achievement metrics. The source needs Gurobi and does not provide a locked deployment environment. Hardcoded Flask session configuration and a shared mutable history field in the global problem instance indicate a local demonstration, not a hardened concurrent service. Describe the nutrient calculations as model inputs; do not imply clinical validation. This is **meal optimization**, with no evidence of vehicle routing or the SIGmile competition award.

## Algorithm Visualizer — interactive algorithm explanations

Revision: [`b900deddb45b3516094ba3451086a092257fd2fc`](https://github.com/CdyTim630/algorithm-visualizer/tree/b900deddb45b3516094ba3451086a092257fd2fc). Declared demo: [Algorithm Visualizer](https://cdytim630.github.io/algorithm-visualizer/).

- **Verified implementation:** React 18, TypeScript, Vite 6, Tailwind and Framer Motion. [The application](https://github.com/CdyTim630/algorithm-visualizer/blob/b900deddb45b3516094ba3451086a092257fd2fc/src/App.tsx) exposes complexity, sorting, dynamic programming, graph traversal, binary search, Dijkstra and topological-sort lessons. [Sorting](https://github.com/CdyTim630/algorithm-visualizer/blob/b900deddb45b3516094ba3451086a092257fd2fc/src/modules/Sorting/SortingModule.tsx) generates snapshots for bubble/selection/merge/quick sort, including merge-tree state and selectable quicksort pivots. [DP](https://github.com/CdyTim630/algorithm-visualizer/blob/b900deddb45b3516094ba3451086a092257fd2fc/src/modules/DynamicProgramming/DPModule.tsx) includes stairs and 0/1 knapsack with 1D/2D views. Controls synchronize playback, pseudocode highlights and explanatory state.
- **Personal role:** Ten reachable commits are attributed to CdyTim. Named iterations include selectable pivots, customized DP/graph controls and light-theme rendering fixes. This supports frontend implementation and iterative teaching interaction design.
- **What to surface:** Explainability through visible algorithm state, editable examples and manual decisions. It complements the resume's teaching/algorithm interests without claiming it was used in a course or contest. Treat pseudocode and state diagrams as the app's output, not performance benchmarks.
- **Publication limits:** The tree has no README or automated test suite. Dijkstra's displayed implementation scans nodes for the next minimum rather than using a heap; do not transfer Water Map's heap implementation or complexity to this project. No measured learning improvement, user count or algorithm-novelty claim is supported.
