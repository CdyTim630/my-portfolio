## Research method and attribution

- The initial [public repository inventory](https://api.github.com/users/CdyTim630/repos?per_page=100) contained 21 repositories, including forks. A subsequent authenticated inventory found 34 accessible repositories, including owned and collaborator access; relevant source and authorship were reviewed without publishing a private organization/repository dump. Later review includes explicitly supplied team repositories, résumé links and authorized private source. Reviewed actual source, README files, Git history and available presentation artifacts; this is a dated evidence ledger, not a claim that every accessible repository is a publishable project.
- Created read-only temporary clones for source review. No external repository was modified. Private source remains private: original descriptions may be published where authorized, while private URLs and source/assets are omitted.
- Read the complete text of the Text-Mining report and relevant presentation pages using `pdftotext`; no PDF was changed or published by this task.
- Separate team membership from ownership. A repository under the user's account, or a fork, is not proof that every component is their work. Commit authorship is supporting evidence, not proof of sole authorship; some EmploYA commits explicitly record AI assistance.
- Distinguish code-verified behavior, report-only descriptions and owner-provided résumé claims. The supplied résumé is valid evidence of the owner’s account of participation and awards; source labels identify claims that were not independently corroborated. Proposed production improvements are labeled as future work.
- External repositories were **inspected, not executed**: their tests and benchmarks were not rerun. This inventory does not certify their security, current service uptime or reported experimental results.

## Social Media Text Mining: report evidence and limitations

Inspected revision: [`a3cbb90`](https://github.com/CdyTim630/Text-Mining2025/tree/a3cbb90), uploaded by CdyTim on 8 January 2026. Project year is 2025, matching the course/repository and study period; the upload date is not presented as the research date.

- [Report](https://github.com/CdyTim630/Text-Mining2025/blob/a3cbb90/文字探勘初論第15組期末報告.pdf) and [slides](https://github.com/CdyTim630/Text-Mining2025/blob/a3cbb90/文字探勘初論第%2015%20組期末報告簡報.pdf) are the only public artifacts in that revision.
- Slides name 陳鼎元、陳羿廷、劉起佑、詹孟瑾. The later owner-supplied résumé specifically describes work on text cleaning, sentence-level filtering, ambiguity handling and transformer-based sentiment classification. The case study now attributes these personal tasks to the résumé. The public report establishes the shared team pipeline, without assigning every stage or demonstrating sole/full code authorship; the former request for a personal contribution statement is superseded.
- Reported pipeline: PRAW and historical web collection for Reddit, Selenium for X, English text cleaning, target-aware sentence filtering, keyword rules plus zero-shot disambiguation, transformer sentiment classification, and Gensim LDA with spaCy/NLTK/WordNet preprocessing.
- **Do not claim Gemini API filtering.** The verified report discusses “Gemini” ambiguity between the AI product and zodiac sign; the method is heuristic/zero-shot classification. API usage is not evidenced.
- Table 2-1 reports Cardiff accuracy 0.69, macro-F1 0.69 and neutral recall 0.93 on **100 manually labeled sentences**. DistilBERT and nlptown are comparison models. These are report claims, not reproduced benchmarks; the site omits the headline numbers and explains the small evaluation instead.
- Limitations explicitly include X's narrow collection time window, English-only data, sarcasm/context challenges, limited labels and short aggregate time series. Correlation with traffic estimates cannot establish causation.
- No executable scripts, annotation records, evaluation split, model configuration, dependency lock or dataset are published. The website labels the diagram as a reported research workflow and does not fabricate code excerpts or a live demo.

## Asset and publication policy

- Prefer actual screenshots and demo recordings with a recorded source revision and capture date. Do not present React architecture diagrams as product screenshots.
- Current EmploYA and text-mining visuals are labeled architecture/workflow diagrams. EmploYA's public video is linked as a recording; a local AVFoundation frame extraction could not decode it, so no unverified still was added.
- `Project.images` supports local image paths, alt text and captions. `Project.video` supports source, optional poster, caption and optional transcript; leave it absent until a usable, authorized clip and accessible description are available.
- Source snippets are short, attributed excerpts from the user's public projects. No upstream codebase, team video or PDF is copied wholesale into this site. Confirm team permission before republishing longer materials or adding third-party assets.
- Attribute résumé-only awards clearly; independent result links can strengthen the record later. Avoid exposing student identifiers, contact details from raw datasets, or confidential competition data in screenshots.
