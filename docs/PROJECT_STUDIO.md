# 作品工作室

入口：`/admin` → **作品工作室**，或直接開啟 `/admin/projects`。沿用既有 Supabase 登入與 `app_metadata.portfolio_admin: true` 管理員權限。

## 本機試用

尚未連接 Supabase 時，可在 `.env.local` 設定 `LOCAL_ADMIN_ENABLED=true` 與至少 32 字元的隨機 `LOCAL_ADMIN_SESSION_SECRET`，執行 `npm run dev:local`。登入頁會提供 **進入本機後台**，不用 Email 或密碼；入口為 `/local-admin`，作品編輯器為 `/local-admin/projects`。

本機模式沿用作品工作室，支援新增、儲存草稿、發布與下架。資料保存於專案根目錄的 `.local-data/projects.json`，重新整理或重啟伺服器後仍保留；草稿只在後台可見，**發布至本機**才會更新這台電腦上的作品集。此資料夾不會提交到 Git 或打包進部署產物，請自行保留備份。

此入口只在開發模式、localhost 且沒有 Supabase 設定時啟用；`dev:local` 將伺服器綁定到本機。正式建置停用本機入口與本機資料讀寫，即使留下環境設定也不會啟用。文章、日記等其他管理功能仍需 Supabase。之後接上 Supabase 時，本機專案不會自動上傳。

## 開通儲存

1. 在 `.env.local` 設定既有專案的 `NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_ANON_KEY`，重新啟動開發伺服器。使用公開 anon / publishable key。
2. 在同一個 Supabase 專案的 SQL Editor 執行根目錄的 `supabase-projects.sql`。這是新增作品資料表的獨立建置檔，不需要重跑歷史文章設定 SQL。
3. 以既有管理員帳號登入，開啟作品工作室。

沒有 Supabase 設定時，公開作品仍使用原有的 20 件作品。尚未建立作品資料表時，後台會提示無法儲存，不會顯示假的成功訊息。

## 編輯與發布

- 從列表選擇既有作品，或新增作品。既有的內容直接成為編輯起點，不必重新輸入。
- 切換中文／英文分別編輯標題、摘要、個人貢獻、內文章節、架構步驟、圖片說明與參考資料。
- 調整分類、排序、首頁精選及列表位置；數字較小的排序在前。年份未知可以留空。
- 圖片使用公開 HTTP(S) 圖片網址，或 `/projects/...` 形式的本機素材路徑；第一張圖用於作品封面。替代文字說明圖片內容，圖說用於畫面下方。
- **儲存草稿**僅更新後台，保留訪客目前看到的版本。
- **發布專案**將目前內容與版位設定一起發布到首頁精選、作品列表與專案內頁。
- **取消發布**移除公開展示，保留草稿供後續編輯。既有內建作品也可以取消發布，不會因為程式內仍有原稿而重新出現。

網址 slug 在第一次儲存後固定；新增作品請使用小寫英文、數字與連字號。公開版本與草稿存放於不同的資料表，匿名訪客不能讀取草稿。

## 資料流

`portfolio_project_drafts` 儲存後台編輯稿；`portfolio_projects` 儲存公開快照。儲存、發布、取消發布由同一個資料庫函式處理，發布中的內容與草稿一起更新。取消發布保留空的公開快照作為下架紀錄。

公開頁面只用匿名 client 讀取公開資料。資料表尚未建立時維持內建作品；已設定資料庫但遇到其他讀取錯誤時，暫停列出作品，以免已下架的內建作品再次出現。恢復資料庫連線後即可恢復展示。

新增或更新後會重新驗證作品首頁、列表、內頁與 sitemap 的快取。資料表建置與實際登入後的資料庫寫入，需要在已設定的 Supabase 環境驗證；本機無憑證的測試不代表已套用遠端資料庫設定。

## 本機驗證

`npm test` 包含資料驗證、草稿與公開版本合併、下架紀錄、API 權限及編輯器操作測試。有 PostgreSQL 的開發環境可以執行 `node scripts/test-project-migration.mjs`；它會建立並清理獨立的暫存資料庫，驗證建置檔可重複執行、草稿不外洩、管理員權限與發布失敗時的交易回滾，不會連線正式 Supabase。
